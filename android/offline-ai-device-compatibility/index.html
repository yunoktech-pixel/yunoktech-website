🧠 Android AI Projects and Production

Offline AI Features and Device Compatibility

Your AI feature works perfectly on a flagship phone on office Wi-Fi. But many users have mid-range devices, limited storage and patchy connectivity. Designing for that reality means detecting capability, delivering models carefully, and offering tiered experiences.

Android runs on thousands of device models. An AI feature has to answer three questions at runtime: can this device run the model, is the model present, and is the network available if we need the cloud? The answers decide which experience the user gets.

Tiered experiences

Detect capability

For Gemini Nano, always use the API's own status check (ML Kit GenAI's checkFeatureStatus()) instead of hard-coding device lists. Supported devices change over time.

Model downloads

  • Download only when the user is likely to use the feature, preferably on unmetered networks.
  • Show progress and size, and allow cancel.
  • Handle storage-full and interrupted downloads, and verify checksums for your own model files.
  • Use WorkManager for large downloads with constraints. See WorkManager.

Designing for offline

  • On-device first for features users need anywhere (dictation, translation, OCR).
  • Queue cloud requests for non-urgent work (summarise later) and notify when done.
  • Be explicit in UI: "Summaries need internet on this device" is better than a spinner that fails.

Testing across devices

  • Test on at least one low-end and one mid-range device, not just flagships.
  • Test airplane mode, flaky networks and low storage.
  • Use Firebase Test Lab or device farms for broad coverage.
  • Log tier selection (without content) to see real-world availability. See Monitoring AI.

Frequently asked questions

Can I make Gemini Nano available on unsupported devices?

No. Use the cloud or your own smaller model through LiteRT-LM as alternatives.

Should I hide AI features on unsupported devices?

Hide them if no tier works. Otherwise show the feature with the available tier and clear messaging.

Conclusion

Design AI features in tiers: on-device when available, cloud when online and allowed, and a non-AI fallback otherwise. Detect capability with official status APIs, download models carefully, and test on real low-end devices and offline.
