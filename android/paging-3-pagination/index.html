Pagination with Paging 3

Loading thousands of items at once wastes data, memory and time. Paging 3 loads data page by page as the user scrolls, handles loading and error states, deduplicates requests, and works with Room for offline caching.

A hand-rolled infinite scroll has to track the current page, avoid duplicate requests while scrolling fast, show a footer spinner, handle errors with retry, reset on refresh, and survive rotation. Paging 3 handles all of this. You implement one function that loads a page.

Where Paging fits

Search results

Network-only PagingSource, recreated per query with flatMapLatest.

Feeds with offline

RemoteMediator plus Room, so cached pages appear instantly and new pages load as needed.

Large local tables

Room's built-in PagingSource for chat history or logs with tens of thousands of rows.

Common mistakes

  • Forgetting cachedIn(viewModelScope), which reloads everything on rotation.
  • Transforming PagingData after cachedIn. Apply map and filter before caching.
  • Missing stable keys in the LazyColumn.
  • Unstable sort order on the server, causing duplicates or gaps between pages.

Frequently asked questions

Can I modify items, such as toggling a like, in paged data?

With RemoteMediator plus Room, update the database and the paged list updates automatically. For network-only paging, invalidate the source or overlay local state.

Should I enable placeholders?

Only if you know the total count and want stable scrollbar sizing. Most apps disable them.

Is Paging overkill for 100 items?

Usually yes. Load them at once into a LazyColumn. Paging shines with large or unbounded datasets.

Conclusion

Paging 3 gives you incremental loading, deduplication, load states and retry for the price of a PagingSource. Cache in the ViewModel, render with LazyPagingItems and stable keys, and add a RemoteMediator with Room for offline-first feeds.
