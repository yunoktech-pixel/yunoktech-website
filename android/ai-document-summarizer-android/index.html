Build an AI Document Summarizer for Android

A document summarizer is a great portfolio project: it combines file access, text extraction, chunking for long inputs, LLM calls, streaming UI and local storage. Here's a complete architecture and the key code for each part.

Architecture

2. Extract text

Plain text is easy. For PDFs, there are several options:

  • Cloud multimodal model: send the PDF directly to Gemini through Firebase AI Logic, which accepts PDFs as inline data (within size limits). Simplest, and handles layout.
  • On-device: render pages with PdfRenderer to bitmaps and run ML Kit text recognition. Private, but slower.
  • A PDF text library: for text-based PDFs. Check licences.

4. Map-reduce summarisation

Run chunk summaries with limited parallelism to stay within rate limits, and stream only the final step. Render it as in Streaming in Compose.

Quality and trust

  • Label summaries as AI-generated, and show which model source was used.
  • Prompt for faithfulness ("use only the text"), and spot-check with an evaluation set. See Evaluating AI.
  • Disclose cloud processing, and offer on-device-only mode for sensitive documents.
  • Handle failures per stage with clear messages.

Extensions

Ask the document

Add Q&A with retrieval. See RAG on Android.

Share target

Accept shared text or files from other apps.

Background processing

Long documents via WorkManager with a completion notification.

Frequently asked questions

How long a document can I summarise?

With map-reduce, length is limited mainly by time and cost. Cap pages or characters and tell users.

Will scanned PDFs work?

Yes, with OCR or a multimodal model, but quality depends on scan quality.

Conclusion

A solid summarizer picks files via SAF, extracts text (or sends PDFs to a multimodal model), chunks long inputs, summarises with map-reduce, streams the final result, and stores history, with clear AI labelling and privacy choices.
