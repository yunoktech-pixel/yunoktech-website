Gemini API Integration in Android Using Kotlin

A complete, production-minded walkthrough for calling Gemini from an Android app in Kotlin: Firebase AI Logic setup, App Check protection, model configuration, streaming responses into Jetpack Compose, sending images, and handling the errors you'll actually see.

Most "Gemini in Android" tutorials stop at one generateContent() call with an API key pasted into BuildConfig. That works in a demo and becomes a security incident in production. This guide builds the feature the way you'd actually ship it.

It's for intermediate Android developers comfortable with Kotlin, coroutines and Compose. You'll integrate Gemini through Firebase AI Logic, Google's recommended client SDK for calling Gemini from mobile apps, protect it with App Check, configure the model, stream output into a Compose screen, send images, and handle errors and cost.

Versions and model names

The SDK and Gemini models evolve quickly. The code below follows the Firebase AI Logic documentation at the time of writing, which uses firebase-ai through the Firebase BoM and the gemini-3.8-flash model in its examples. Check the current models page and Firebase release notes before you ship.

How the pieces fit

Step 1: Set up Firebase and AI Logic

  1. Create or open a Firebase project in the Firebase console and register your Android app with its exact package name.
  2. Enable Firebase AI Logic in the console and choose a Gemini API provider. The Gemini Developer API has a no-cost tier for getting started. Vertex AI Gemini API suits enterprise and Google Cloud requirements.
  3. Download google-services.json into your app/ directory.
  4. Add the Google services plugin and dependencies as shown below.

Step 2: Protect the endpoint with App Check

Because the app calls Gemini through Firebase, anyone who copies your Firebase configuration could try to call it too. App Check attaches an attestation token, from Play Integrity on real devices, so Firebase can reject requests that don't come from your genuine app. Firebase's documentation states that App Check is enforced for AI Logic from July 2026, so set it up from day one.

Debug tokens are secrets

The debug provider logs a debug token, which you register in the Firebase console. Don't commit it to a public repository, and never ship a debug build or debug provider in production.

Cost and abuse control

  • Cap input and output. Truncate user input (the take(500) above) and set maxOutputTokens.
  • Ask for brevity in the prompt. "Under 150 words" reduces output tokens and latency.
  • Debounce and deduplicate. Never call the model on every keystroke.
  • Cache deterministic results such as "explain topic X", keyed by input and prompt version.
  • Add per-user quotas. If you need them, or need multiple providers or private data retrieval, move calls behind your own backend.
  • Monitor usage in the Firebase and Google Cloud consoles, and set budget alerts.

Use cases this pattern fits

Learning app: "Explain this concept"

Short, bounded prompts with a system instruction for tone. Streaming makes answers feel instant. Low risk, high value.

Accessibility: alt text for user photos

Multimodal input generates draft descriptions that the user reviews and edits before posting. Labelled as AI-generated.

Content app: title and tag suggestions

Suggest, don't decide: the user picks from the generated options. Cache results per item.

Frequently asked questions

Can I put a Gemini API key in BuildConfig instead?

You shouldn't. Anything in an APK can be extracted, and a leaked key can be abused at your expense. Use Firebase AI Logic with App Check, or your own backend.

What happened to the old Google AI client SDK for Android?

Google now directs Android developers to Firebase AI Logic for calling Gemini from mobile apps. If you have older code using the previous client SDK, migrate it following Firebase's migration guide.

Gemini Developer API or Vertex AI?

The Gemini Developer API is the quickest start and has a no-cost tier. Vertex AI suits organisations that need Google Cloud enterprise controls and data governance. Firebase AI Logic supports both, and switching is mostly a backend parameter change.

How do I build a multi-turn chat?

Use model.startChat(history) and sendMessageStream(). The full project, including history trimming, is in Build an AI Chatbot with Kotlin and Jetpack Compose.

Does this work offline?

No, cloud models need connectivity. For offline features, see Gemini Nano and ML Kit GenAI or hybrid inference.

Conclusion

A production-ready Gemini integration is more than one API call: Firebase AI Logic for the SDK, App Check for protection, a system instruction and generation limits for predictable output, streaming state in the ViewModel, and honest error handling in the UI. With those pieces in place, adding a new AI feature is mostly a matter of writing a good prompt.
