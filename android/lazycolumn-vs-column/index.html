LazyColumn vs Column: When to Use Each

Column lays out all of its children at once. LazyColumn composes only what's on screen. Choosing the right one, and using keys and contentType properly, is the difference between a smooth feed and a janky one.

A new Compose developer builds a feed with Column(Modifier.verticalScroll(...)) and forEach. It works with 20 items. With 2,000 it takes seconds to open and stutters while scrolling. The fix is one word, Lazy, plus a few details that matter more than they look.

The core difference

AspectColumnLazyColumn
ComposesAll children immediatelyVisible items (plus prefetch)
ScrollingNeeds Modifier.verticalScrollBuilt in
Good forSmall, fixed content: forms, detail pages, settings sectionsLong or unbounded lists: feeds, search results, chats
APINormal composable childrenDSL: item, items, stickyHeader
Scroll staterememberScrollState()rememberLazyListState() (index-based)

LazyColumn done right

  • key: without stable keys, inserting at the top shifts item state (such as an expanded card) to the wrong rows, and scroll position jumps. Use your item's ID.
  • contentType: tells Compose which items share structure, so it can reuse work efficiently in mixed lists.
  • Modifier.animateItem() animates insertions, removals and reordering.

When Column is the better choice

With a small, bounded number of children, a Column is simpler, and laziness adds overhead without benefit.

The nested scrolling trap

Putting a LazyColumn inside a Column with verticalScroll throws an error, because a lazy list can't be measured with infinite height. Don't nest them. Make the whole screen one LazyColumn and put the header content in item { } blocks:

Horizontal lists inside a vertical LazyColumn (a LazyRow per section, like a store front) are fine and common.

Scroll state and actions

For real paging from APIs or databases, prefer Paging 3, which handles loading states, retries and caching.

Performance tips

  • Keep item composables cheap. Precompute formatted strings in the ViewModel.
  • Load images at the item's display size with an image library.
  • Avoid reading listState directly in the item builder. Wrap derived values in derivedStateOf.
  • Judge scrolling smoothness on release builds with Baseline Profiles. See Compose Performance Optimization.

Choosing in practice

Settings screen (15 rows)

Either works. A Column is simpler. Choose LazyColumn if the rows come from data and may grow.

Product grid

LazyVerticalGrid or LazyVerticalStaggeredGrid with keys.

Chat

LazyColumn(reverseLayout = true) keeps the newest messages at the bottom, anchored as new ones arrive.

Frequently asked questions

Is LazyColumn the same as RecyclerView?

Conceptually similar: both render only what's visible. LazyColumn needs no adapter or ViewHolder, and diffing is driven by keys.

Why does my item's remembered state reset when scrolling?

Items leaving the screen are disposed. Hoist important state into the item model or ViewModel, or use rememberSaveable with stable keys.

Can I use LazyColumn inside a Scaffold?

Yes. Pass the Scaffold's padding values to contentPadding so items aren't hidden behind bars.

Conclusion

Use Column for small, fixed content and LazyColumn for lists that can grow. Give lazy items stable keys and contentType, never nest a lazy list inside a scrolling Column, and keep item composables cheap.
