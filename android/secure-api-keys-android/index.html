Secure API Keys and Secrets in Android Apps

'How do I hide my API key in Android?' is one of the most asked questions, and the honest answer is that you can't hide a secret in an APK. What you can do is decide which keys may live in the app, restrict them, and keep real secrets on a server.

An APK is a zip file. Its strings, BuildConfig constants, resources and even native libraries can be extracted with free tools in minutes. Obfuscation and NDK tricks slow attackers slightly, and runtime interception defeats them anyway. Design as if every key in the app is public.

Keeping keys out of source control

Even for keys that are allowed in the app, avoid committing them to Git, where they're scraped quickly from public repos. The Secrets Gradle Plugin reads values from local.properties (which is ignored by Git) and exposes them as BuildConfig fields and manifest placeholders:

This hides keys from Git, not from the APK

The value still ends up in the built app. That's fine for restricted client keys, and never acceptable for real secrets.

Restrict client keys

  • Application restrictions: limit to your package name and signing certificate SHA-1 (include the Play App Signing certificate).
  • API restrictions: allow only the APIs the app uses.
  • Quotas and alerts: cap usage and alert on spikes.

Remember that app restrictions rely on request metadata that a determined attacker can spoof. They limit casual abuse, not targeted attacks.

Real secrets: use a backend

For Gemini specifically, Firebase AI Logic with App Check provides this mediation without your own server. See Integrating Cloud AI APIs Securely.

If a secret leaks

  1. Revoke or rotate the key immediately in the provider console.
  2. Check usage logs and billing for abuse.
  3. Remove it from history (rewrite Git history if needed) and from any published APKs, by releasing an update.
  4. Fix the architecture so the secret no longer needs to be in the app.
  5. Enable secret scanning on your repositories.

Frequently asked questions

What about storing keys in native (C++) code?

It adds a small amount of effort for attackers, who can still extract them from the binary or intercept them at runtime. It isn't a substitute for keeping secrets server-side.

Can I fetch the key from my server at runtime?

Then it's in device memory and network traffic, so still exposed. Instead, have the server make the call that needs the key.

Is google-services.json a secret?

It contains project identifiers meant to be in the app. Protect your Firebase data with Security Rules and App Check instead.

Conclusion

You can't hide secrets in an APK. Ship only public or restricted client keys, keep them out of Git with the Secrets Gradle Plugin, put real secrets behind a backend (or Firebase AI Logic with App Check for Gemini), and have a rotation plan for leaks.
