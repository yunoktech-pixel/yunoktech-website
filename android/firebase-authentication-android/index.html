Firebase Authentication in Android

Firebase Authentication gives Android apps secure sign-in without building an auth backend: email and password, Google, phone and more. This guide implements email and Google sign-in with modern APIs, exposes auth state as a Flow, and connects it securely to your own server.

Rolling your own authentication means hashing passwords, securing reset flows, rate-limiting attacks and managing sessions, all of which are easy to get dangerously wrong. Firebase Authentication handles these as a managed service, while your app focuses on the sign-in experience.

How it fits together

Setup

  1. Create a Firebase project, register your Android app, and add google-services.json.
  2. Enable the providers you need (Email/Password, Google) in Authentication → Sign-in method.
  3. For Google sign-in, add your app's SHA-1 and SHA-256 fingerprints (debug and release, plus Play App Signing) in project settings.

Calling your own backend securely

Your server must verify the ID token with the Firebase Admin SDK and use the verified UID, never a user ID sent in the request body. If you use Firestore or Realtime Database, protect data with Security Rules based on request.auth.

Depending on your project's settings, Firebase may return a generic invalid-credential error instead of revealing whether an email exists. Design messages that work either way.

Common setups

Consumer app

Google sign-in as the primary option, email as a fallback, and optional anonymous auth to let users try first and link later.

App with its own API

Firebase for identity, your backend verifying ID tokens and storing app data.

Sensitive actions

Re-authenticate before changing email or deleting an account, and consider biometrics for local unlock.

Common mistakes

  • Missing release or Play App Signing SHA fingerprints, so Google sign-in works in debug but fails in production.
  • Trusting client-provided user IDs on the server.
  • Storing passwords locally.
  • Not offering account deletion. Google Play requires apps that allow account creation to provide account deletion.

Frequently asked questions

Does Firebase Auth keep users signed in?

Yes. Sessions persist across app restarts until the user signs out or the session is revoked. ID tokens refresh automatically.

Should I use the old Google Sign-In SDK?

Google recommends Credential Manager for new implementations of Sign in with Google on Android.

Is Firebase Auth free?

Many providers have a generous free tier, but some features (such as phone authentication and enterprise features) have usage-based pricing. Check current Firebase pricing.

Conclusion

Firebase Authentication provides managed, secure identity. Expose auth state as a Flow, use Credential Manager for Google sign-in, send ID tokens to your backend and verify them server-side, and map auth errors to clear messages.
