Evaluating AI Responses and Reducing Hallucinations

AI features fail differently from normal code: the same input can produce different outputs, and wrong answers look confident. You can't unit-test your way to quality alone. You need evaluation datasets, layered checks and techniques that reduce hallucinations in the first place.

A hallucination is output that's fluent but unsupported or false: a made-up refund policy, an invented API method, a wrong date. Models can't be made hallucination-free, but systems can make hallucinations rarer, easier to detect, and less harmful.

Reducing hallucinations by design

  • Ground answers in retrieved documents or tool results, not model memory. See RAG and Function Calling.
  • Constrain: narrow tasks, schemas, low temperature for factual work.
  • Permit uncertainty: instruct "if the answer isn't in the context, say you don't know", and reward it in evaluation.
  • Verify: validate structured fields, check that citations exist, cross-check numbers against your data.
  • Contain: show sources, let users edit, and avoid AI-only decisions in high-stakes domains.

Build a golden evaluation set

Collect 50–200 realistic inputs (with consent and anonymisation) covering common cases, edge cases, other languages, adversarial inputs, and questions that should be refused. For each, note what a good answer must contain or avoid.

Automated checks, from cheap to expensive

LLM-as-judge needs care

Judges have their own biases and errors. Use clear rubrics, check them against human ratings on a sample, and never treat their scores as ground truth.

Regression testing

  1. Run the evaluation set whenever you change the prompt, model, retrieval or temperature.
  2. Compare pass rates per category against the previous version.
  3. Block releases on significant drops, and review failures manually.
  4. Record prompt and model versions with results.

Learning from production

  • Add thumbs up/down and "report" on AI outputs, and capture the reason.
  • Track acceptance, edit and regeneration rates for suggestions.
  • Sample and review conversations (with consent and privacy safeguards), then add failures to the golden set.

Applying it

Help assistant

Golden questions per help article, plus "not covered" questions that must be refused, with citation checks.

Extraction

Field-level accuracy against labelled receipts, and schema validation on every response.

Writing suggestions

Acceptance rate, plus checks that names and numbers are preserved.

Frequently asked questions

Can I eliminate hallucinations?

No. You can reduce and contain them. Design features so occasional errors are visible, correctable and low-impact.

How often should I run evaluations?

On every prompt, model or retrieval change, and periodically, since providers update models.

Is temperature 0 deterministic?

Not always across calls or model versions. Treat evaluation results statistically, and run each case more than once for critical features.

Conclusion

Quality AI features combine prevention (grounding, constraints, permission to say "I don't know"), verification (validation, citation checks) and evaluation (golden datasets, regression runs, production feedback). Treat quality as an ongoing process, not a launch checklist.
