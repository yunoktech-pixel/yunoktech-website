RAG for Android Apps: Connecting AI to Your Own Data

General models don't know your product manuals, course notes or a user's own documents, so they guess. Retrieval-augmented generation (RAG) fixes that by finding relevant passages first and asking the model to answer only from them. Here's how to build RAG for Android, server-side and on-device.

Ask a general model "What's the return window for electronics in our app?" and it will produce a plausible answer that may be wrong for your policy. With RAG, the system first retrieves your actual returns policy, then asks the model to answer from it, and the answer can cite where it came from.

How RAG works

Server-side or on-device?

DataWhereWhy
Shared knowledge (help centre, product catalogue, course content)ServerIndex once; access control; update without app releases
Private user data (notes, files on the device)On-device retrieval; on-device or consented cloud generationPrivacy; offline
Enterprise or multi-tenant dataServer with strict per-user authorisationPrevent cross-user leakage

1. Chunking

  • Split by structure (headings, paragraphs), with chunks of a few hundred words and small overlaps.
  • Store metadata: source title, URL or section, updated date, and who may access it.
  • Re-index when documents change.

2. Retrieval

Embed the question with the same embedding model used for chunks, retrieve the top matches, filter by the user's permissions, and optionally re-rank. Hybrid keyword + vector retrieval often improves results for names and codes. See AI-Powered Search.

3. Grounded prompt with citations

Configure the model for JSON output with a schema where possible, and keep temperature low.

The Android side

Security and access control

  • Authorise retrieval: filter chunks by the user's permissions before they reach the prompt. The model can't be trusted to keep secrets it was shown.
  • Treat documents as untrusted: retrieved text can contain injected instructions. Keep the model's abilities narrow. See Prompt Injection.
  • Privacy: don't index personal data unless necessary, and support deletion.

Evaluating RAG

  • Retrieval quality: for test questions, are the right passages in the top-k results?
  • Answer faithfulness: are answers supported by the cited passages?
  • Refusal correctness: does it say "I don't know" when the docs don't cover the question?

See Evaluating AI Responses and Reducing Hallucinations.

Use cases

In-app help

Answers from the help centre with source links, plus a handoff to support.

Course assistant

Answers grounded in lesson notes. See AI Study Assistant.

Personal knowledge

On-device retrieval over the user's own notes, for privacy.

Frequently asked questions

Doesn't a long-context model make RAG unnecessary?

Long context helps, but sending everything every time is slow and costly, and access control still requires selecting what each user may see. Retrieval remains useful.

How many passages should I retrieve?

Start with 3–8, tune by evaluation, and balance recall against prompt size and cost.

Can RAG still hallucinate?

Yes, less often. Require citations, verify that cited IDs exist, use low temperature, and evaluate faithfulness.

Conclusion

RAG grounds AI answers in your data: chunk and embed documents, retrieve authorised passages, prompt the model to answer only from them with citations, and evaluate retrieval and faithfulness. Run it on the server for shared knowledge and on-device for private data.
