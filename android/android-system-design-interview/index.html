Android System Design Interview Questions

Mobile system design interviews ask you to design an app, such as a chat app, a news feed or a photo gallery, end to end from the client's perspective. The skill being tested is structured thinking about constraints, data flow and trade-offs, not drawing boxes quickly.

"Design Instagram's feed" isn't a request to rebuild Instagram in 45 minutes. It's an invitation to show how you clarify requirements, choose a client architecture, handle network and storage constraints, and reason about trade-offs, while communicating clearly.

A framework for the interview

Step 1: Clarify

  • Functional: core features for this interview (for example: view feed, like, comment, post photo).
  • Non-functional: offline support? Real-time? Scale (users, items per screen)? Low-end devices? Battery and data constraints?
  • Out of scope: confirm what you'll skip (for example the ranking algorithm and server internals).

Step 2: API and data models

Mention cursor-based pagination (stable under inserts), idempotency for actions, and image URLs with size variants.

Worked example prompts

Design a chat app

Local message store, send queue with states (sending, sent, failed), WebSocket while open, FCM otherwise, ordering with server IDs, attachments uploaded in the background.

Design an offline notes app with sync

Room, client UUIDs, change log, periodic and on-change sync, last-write-wins or field merge, end-to-end encryption options.

Design an image gallery

MediaStore or Photo Picker, paging thumbnails, memory budgets, decoding off the main thread, and large-screen layouts.

Step 5: Trade-offs to volunteer

  • Consistency vs responsiveness (optimistic UI).
  • Real-time freshness vs battery and data.
  • Offline capability vs complexity and storage.
  • Modularization vs speed for a small team.

Frequently asked questions

How much backend detail is expected?

Mostly API contracts and client implications. Mention server concerns briefly (rate limits, idempotency), and stay focused on the client.

Should I write code?

Usually only small snippets or interfaces. Diagrams and clear explanations matter more.

Conclusion

Ace mobile system design by clarifying constraints, defining APIs and models, presenting a clear client architecture, going deep on offline, pagination, real-time and media, and volunteering trade-offs, all while thinking out loud.
