Retrofit in Android: Complete Guide

Retrofit turns an HTTP API into a Kotlin interface. Combined with coroutines and kotlinx.serialization, a network call becomes a single suspend function. This guide covers setup, every common request type, configuration, error handling and testing.

Most Android apps talk to a REST API. Writing raw HTTP code (building URLs, encoding JSON, parsing responses, handling threads) is repetitive and error-prone. Retrofit, from Square, generates all of that from an annotated interface, and it's the most widely used HTTP client in the Android ecosystem.

Calling from a repository

Retrofit's suspend functions are main-safe: OkHttp performs the I/O on its own threads, so you can call them from viewModelScope directly.

Errors

  • Non-2xx responses throw HttpException (with code()) when the return type isn't Response<T>.
  • Network failures (no connection, timeouts) throw IOException.
  • Malformed JSON throws a SerializationException.

Common mistakes

  • Creating a new Retrofit or OkHttp instance per request, which wastes connection pools and caches.
  • Base URL without a trailing slash, or leading slashes in endpoint paths, which produce surprising URL resolution.
  • Strict JSON parsing without ignoreUnknownKeys, so new server fields crash old app versions.
  • Using DTOs directly in UI state. Map them to domain models.
  • Logging sensitive data in production.

Frequently asked questions

Gson, Moshi or kotlinx.serialization?

For Kotlin-first apps, kotlinx.serialization respects default values and nullability and works with Kotlin Multiplatform. Moshi is also solid. Gson ignores Kotlin nullability and defaults, so it's less suited to new Kotlin code.

Do I need Dispatchers.IO for Retrofit calls?

No. Suspend Retrofit functions are already main-safe.

How do I cancel a request?

Cancel the coroutine. Retrofit cancels the underlying OkHttp call automatically.

Conclusion

Retrofit + OkHttp + kotlinx.serialization + coroutines give you type-safe, concise, main-safe networking. Share one configured client, tolerate unknown JSON fields, map DTOs to domain models, handle errors centrally, and test with MockWebServer.
