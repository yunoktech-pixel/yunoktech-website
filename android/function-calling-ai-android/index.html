Function Calling and Tool Use in AI-Powered Apps

Function calling lets a model decide that it needs your app's data or actions, such as checking an order, finding a store or creating a reminder, and request them in a structured way. Your code stays in control: it validates, executes and returns results. Here's how to do it safely in Kotlin.

A support chatbot that can only talk is limited. One that can look up your order is useful. Function calling bridges the two: you describe functions to the model, it returns a structured request to call one with arguments, your code runs it, and the model uses the result to answer.

Safety rules for tool use

  • Allow-list functions, and never execute arbitrary names or code from the model.
  • Validate every argument (type, format, ranges), just like untrusted user input.
  • Authorise in your code: the tool queries only the signed-in user's data.
  • Confirm sensitive actions: payments, cancellations, sending messages and deleting data need an explicit user confirmation in the UI, not just model intent.
  • Limit the loop: cap iterations and time.
  • Read-only first: start with lookups, and add actions carefully.

Use cases

Support assistant

Order status, return eligibility and store lookup, all read-only with user scoping.

Voice commands

"Remind me at 6" → createReminder(time, title) → confirm → create.

Smart filters

"Show red shoes under 3000" → applyFilters(...), which only changes UI state.

Frequently asked questions

Can the model call functions on its own without my code?

No. The model only returns a request. Nothing runs unless your code executes it.

Function calling or structured output?

Structured output returns data in a schema in one step. Function calling lets the model decide whether and which tool to use, often over multiple turns.

How does this relate to Android AppFunctions?

AppFunctions let your app expose functions to system-level AI agents. In-app function calling is your own assistant calling your own code. See AppFunctions.

Conclusion

Function calling turns AI from a talker into a helper: declare narrow tools, validate and authorise every call in your code, return structured results, cap the loop, and require user confirmation for actions. The model proposes, and your app decides.
