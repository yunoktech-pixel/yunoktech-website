AI-Assisted Unit Test Generation for Android

AI can write dozens of unit tests in seconds, and many of them will test nothing useful. The trick is to make AI think about behaviour and edge cases first, use your test conventions, and review tests as critically as production code.

An AI-generated test that calls a function and asserts the result is "not null" adds coverage and no safety. Good tests encode behaviour: given this situation, the app must do that. AI can help enumerate situations, and you decide which behaviours matter.

Recognising weak AI tests

SmellExampleFix
Asserts nothing meaningfulassertNotNull(vm.uiState.value)Assert specific state values
Mirrors the implementationRecomputes the expected total with the same formulaUse known, hand-calculated values
Over-mockingVerifies every repository callUse fakes; assert outcomes
Flaky timingThread.sleep, real dispatchersTest dispatchers, virtual time
Tests framework behaviourAsserting Room or Retrofit internals in unit testsTest your logic; integration tests elsewhere

Check that tests can fail

Manually introduce a bug (flip a condition, remove a guard) and run the tests. At least one should fail. Mutation-testing tools automate this idea on the JVM, but even a few manual mutations reveal hollow tests quickly.

Where AI test generation pays off

Legacy code with no tests

AI drafts characterization tests capturing current behaviour before a refactor. See Refactoring Legacy Apps.

Mappers and validators

Table-driven tests of many input variations, with hand-checked expected values.

Edge-case discovery

The brainstorm step often surfaces cases the team missed, such as double taps, empty states and time zones.

Frequently asked questions

Should coverage targets drive AI test generation?

No. Coverage encourages hollow tests. Target behaviours and risks, and use coverage only to find untested risky code.

Can AI generate UI tests?

It can draft Compose UI tests and screenshot previews, but they need the same review: realistic states, stable selectors and meaningful assertions.

What about Android Studio's test generation?

Gemini in Android Studio can generate unit tests for a class. Treat the output as a draft, and apply the review steps above.

Conclusion

Use AI to enumerate edge cases and draft tests in your conventions, then curate them, prove they fail when code breaks, and delete hollow ones. Good AI-assisted tests protect behaviours, not coverage numbers.
