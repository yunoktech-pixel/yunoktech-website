How to Set Up Android Studio Step by Step

A clean Android Studio setup saves you hours of confusing errors later. Follow these steps to install the IDE, the SDK and an emulator, connect a real phone, run your first project, and fix the setup problems beginners hit most often.

Many beginners lose their first weekend to setup problems: a Gradle sync that never finishes, an emulator that won't start, a phone that Android Studio can't see. None of these mean Android is too hard. They're configuration issues with known fixes.

This guide walks you through a clean installation on Windows, macOS or Linux, explains what each component is for, and covers the errors you're most likely to meet.

Before you install: system requirements

Google publishes the official minimum requirements on the install page. In practice:

  • RAM: 16 GB makes Android Studio plus the emulator comfortable. With 8 GB, prefer a physical phone over the emulator.
  • Disk: an SSD with plenty of free space. The SDK, system images and Gradle caches grow over time.
  • CPU: a 64-bit processor with virtualisation support (Intel VT-x or AMD-V, enabled in BIOS/UEFI) for a fast emulator.

Step-by-step installation

  1. Download the latest stable Android Studio from developer.android.com/studio. Avoid third-party download sites.
  2. Run the installer. On Windows, run the .exe and keep the default components. On macOS, drag Android Studio to Applications. On Linux, unpack the archive and run studio.sh from bin/.
  3. Complete the Setup Wizard. Choose Standard setup. It downloads the latest Android SDK, platform tools and an emulator system image.
  4. Accept the SDK licences when prompted, and wait for the downloads to finish completely.
  5. Open the SDK Manager (Settings → Languages & Frameworks → Android SDK) and confirm a recent Android platform and Android SDK Platform-Tools are installed.

Create and run your first project

  1. Choose New Project → Empty Activity. Recent templates use Jetpack Compose.
  2. Set a name and a package name such as com.yourname.firstapp. The package name becomes your app's permanent ID on Google Play, so choose carefully for real apps.
  3. Keep Kotlin and the Kotlin DSL (build.gradle.kts). Leave the suggested minimum SDK unless you have a reason to change it.
  4. Click Finish and wait for the first Gradle sync. The first one downloads Gradle and libraries and can take several minutes.
  5. Pick a device from the toolbar and press Run.

Set up an emulator

Open Device Manager → Create Virtual Device, pick a phone profile, then select a recent system image (an image with Google Play is useful for testing Play services features). Make sure hardware acceleration is working, because the emulator is very slow without it:

  • Windows: enable virtualisation in BIOS/UEFI and use the Windows Hypervisor Platform as described in Google's acceleration guide.
  • macOS: acceleration is built in.
  • Linux: install and enable KVM.

Run on a physical phone

  1. On the phone, open Settings → About phone and tap Build number seven times to enable Developer options.
  2. In Developer options, enable USB debugging, or Wireless debugging on supported versions.
  3. Connect via USB and accept the Allow USB debugging? prompt on the phone.
  4. Your phone appears in Android Studio's device list. Windows may need the manufacturer's USB driver.

Recommended settings for beginners

  • Turn on auto-import (Editor → General → Auto Import) for Kotlin, so imports are added as you type.
  • Learn three shortcuts: Search Everywhere (double Shift), Find Action, and Reformat Code.
  • Use Logcat filters, such as package:mine, to see only your app's logs.
  • Keep Android Studio updated on the stable channel, and update the Android Gradle Plugin with the built-in Upgrade Assistant.

Troubleshooting common setup errors

ProblemLikely causeFix
Gradle sync takes forever or failsSlow or blocked network, proxy, antivirus scanning the Gradle cacheCheck network and proxy settings; exclude the project and .gradle folders from real-time antivirus scanning; retry the sync
"SDK location not found"Missing local.properties or SDK pathSet the SDK path in the SDK Manager; Android Studio writes local.properties
Emulator won't start or is very slowVirtualisation disabled or hypervisor conflictEnable VT-x/AMD-V in BIOS; follow Google's emulator acceleration guide
Phone not detectedUSB debugging off, charge-only cable, missing driverEnable debugging, use a data cable, install the OEM driver, accept the prompt
"Incompatible Gradle JVM"Project uses a JDK version the build doesn't supportSettings → Build Tools → Gradle → Gradle JDK: choose the bundled JDK
Disk fills upSystem images and Gradle cachesDelete unused AVDs and system images; clear old Gradle caches

Setups for different situations

Laptop with 8 GB RAM

Skip the emulator, debug on your phone over USB or Wi-Fi, and close other heavy apps while building.

College lab or shared PC

Install the SDK in a path without spaces or special characters, and keep projects in your user directory to avoid permission errors.

Office behind a proxy

Configure the HTTP proxy in Android Studio and in gradle.properties, because Gradle downloads separately from the IDE.

Frequently asked questions

Do I need to install Java (JDK) separately?

Usually not. Android Studio bundles a JDK (the JetBrains Runtime), and new projects use it by default. See SDK vs JDK vs Gradle for details.

Which Android version should my emulator run?

Use a recent version for daily development, and create one more AVD near your app's minSdk to catch compatibility issues.

Can I use VS Code instead of Android Studio?

It's possible to build from the command line with any editor, but Android Studio's debugger, Compose previews, profilers and emulator integration make it the practical choice, especially for beginners.

Should I use the Beta or Canary channel?

Use Stable for learning and production work. Preview channels are for trying upcoming features and may have bugs.

Conclusion

A working setup has four parts: Android Studio, the Android SDK, a fast emulator or connected phone, and a successful Gradle sync. Most setup errors come from virtualisation, networking, drivers or JDK settings, and all of them are fixable with the table above.
