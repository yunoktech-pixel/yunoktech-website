Kotlin Generics and Reified Types

Generics let you write one piece of code that works safely with many types: a Result wrapper, a cache, a paging helper. Variance and type erasure confuse many developers. This guide explains them with Android examples, and shows how reified types solve erasure for inline functions.

You've used generics since your first List<String>. Writing your own is a different matter: why can't you pass a List<Dog> where a MutableList<Animal> is expected? Why does T::class fail inside a function? This guide answers those questions with code you'd actually write in an Android app.

Type parameters and constraints

Failure uses Nothing, the type with no values and a subtype of everything. Thanks to out T (covariance, explained next), an Outcome<Nothing> is usable as an Outcome<User>.

Variance: in and out

Variance answers a question: if Dog is a subtype of Animal, is Box<Dog> a subtype of Box<Animal>? It depends on whether the box produces or consumes values.

Kotlin uses declaration-site variance (interface Source<out T>). You can also use use-site variance (fun copy(from: Array<out Any>, to: Array<Any>)) for classes you don't control.

Star projection

List<*> means "a list of some specific but unknown type". You can read elements as Any? but can't add anything. It's useful when you only need type-independent operations, such as size.

Common mistakes

  • Over-generalising: a BaseRepository<T, ID, DTO, ENTITY> that every feature fights against. Generic code should remove duplication, not create puzzles.
  • Using Any and casts instead of type parameters.
  • Forgetting that reified requires inline, and that inline functions can't be called from Java with the reified behaviour.
  • Unchecked casts (as List<User>) that hide erasure problems until runtime.

Frequently asked questions

What's the difference between T, T? and T : Any?

A type parameter T may itself be nullable unless bounded by T : Any. T? explicitly allows null. Use T : Any when you need non-null values.

Is Kotlin's out the same as Java's ? extends?

Yes in meaning. out T corresponds to ? extends T, and in T to ? super T. Kotlin adds declaration-site variance so you rarely need wildcards.

Do reified functions increase app size?

Inline functions duplicate their body at each call site, so keep them small. R8 also optimises in release builds.

Conclusion

Generics give you reusable, type-safe code. Variance (out for producers, in for consumers) explains which substitutions are safe. Erasure removes type arguments at runtime, and reified parameters in inline functions bring them back where you need them.
