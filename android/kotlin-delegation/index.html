Kotlin Delegation and Property Delegates

Every time you write by viewModels(), by lazy or var x by remember { }, you're using Kotlin delegation. Understanding how delegates work lets you remove boilerplate, prefer composition over inheritance, and write your own reusable property behaviours.

Kotlin's by keyword shows up everywhere in Android code: private val vm: MainViewModel by viewModels(), val db by lazy { … }, var count by remember { mutableIntStateOf(0) }. They look like magic, but they're one simple language feature applied in two ways: class delegation and property delegation.

Property delegation: how by works

For val x by D, the compiler routes reads of x to D.getValue(thisRef, property), and for var, writes to D.setValue(...).

Validated settings

Common mistakes

  • Using by lazy for values that depend on a Context or View that may be replaced, such as Fragment views, which leaks old instances.
  • Forgetting the imports androidx.compose.runtime.getValue and setValue. Without them, by remember doesn't compile.
  • Hiding heavy work (I/O) inside getValue, where it's invisible to readers and may run on the main thread.
  • Class delegation to a mutable reference: by real captures the object at construction, so reassigning a var later doesn't change the delegate.

Frequently asked questions

Is by lazy the same as lateinit?

No. lazy is for vals computed on first access. lateinit is for vars assigned later from outside. See Kotlin Null Safety.

Does delegation have a performance cost?

A small one: an extra object and an indirect call. It's negligible for typical use. The compiler can also optimise some cases.

Can interfaces with default methods be delegated?

Yes. Delegation forwards all interface members, including those with default implementations, to the delegate.

Conclusion

Class delegation gives you composition and decorators without boilerplate. Property delegation moves storage and access logic into reusable objects, from lazy and viewModels() to Compose's by remember. Once you see the getValue/setValue mechanism, these idioms stop being magic.
