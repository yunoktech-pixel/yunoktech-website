🧪 Testing, Debugging, and Performance

Testing ViewModels with Coroutines and Flow

ViewModels launch coroutines on Dispatchers.Main, collect Flows and use delays, all of which make naive tests hang, flake or pass for the wrong reason. With kotlinx-coroutines-test and a few patterns, ViewModel tests become fast and deterministic.

The first ViewModel test many developers write fails with "Module with the Main dispatcher had failed to initialize". The second passes, even though the code is broken, because the assertion ran before the coroutine finished. Both come from not controlling dispatchers and time.

The testing model

1. Replace Dispatchers.Main

UnconfinedTestDispatcher starts coroutines eagerly, which suits simple state assertions. StandardTestDispatcher queues them until you advance the scheduler, which suits testing intermediate states such as Loading.

The ViewModel under test

2. Tests with virtual time

Passing mainRule.testDispatcher to runTest makes the test and viewModelScope share one scheduler, so advancing time affects both.

3. Turbine for flow assertions

Turbine's test {} collects in order and fails on unexpected or missing emissions. That's excellent for testing sequences.

4. Inject the other dispatchers too

If a repository uses withContext(Dispatchers.IO) directly, tests run that code on real threads and lose determinism. Inject dispatchers and pass the test dispatcher in tests. See Hilt qualifiers.

5. SavedStateHandle

What to cover

Happy path

The event leads to the expected final state.

Failure paths

Network errors, empty results and retries.

Timing

Debounce, timeouts and cancellation of outdated requests.

Common mistakes

  • Using Thread.sleep or real delays in tests.
  • Asserting stateIn(WhileSubscribed) values without any collector, so the upstream never runs.
  • Creating a new StandardTestDispatcher() in the rule and another in runTest, giving two schedulers where time doesn't advance together.
  • Using runBlocking instead of runTest, which runs real time and is slow.

Frequently asked questions

Why does runTest skip my delays?

That's the point: virtual time. delay(5_000) completes instantly when the scheduler advances.

Do I need Turbine?

No, collecting into a list works. Turbine makes sequence assertions clearer and fails fast on unexpected events.

How do I test LiveData?

Use InstantTaskExecutorRule from androidx.arch.core:core-testing, or convert to Flow with asFlow().

Conclusion

Deterministic ViewModel tests need three things: Main replaced with a test dispatcher, runTest sharing that scheduler, and injected dispatchers everywhere else. Collect StateFlows in backgroundScope or use Turbine, and drive time explicitly.
