You've used generics since your first List<String>. Writing your own is a different matter: why can't you pass a List<Dog> where a MutableList<Animal> is expected? Why does T::class fail inside a function? This guide answers those questions with code you'd actually write in an Android app.

Type parameters and constraints

sealed interface Outcome { data class Success(val value: T) : Outcome data class Failure(val error: Throwable) : Outcome } inline fun Outcome.map(transform: (T) -> R): Outcome = when (this) { is Outcome.Success -> Outcome.Success(transform(value)) is Outcome.Failure -> this } suspend fun runCatchingIo(block: suspend () -> T): Outcome = try { Outcome.Success(block()) } catch (e: IOException) { Outcome.Failure(e) }

Failure uses Nothing, the type with no values and a subtype of everything. Thanks to out T (covariance, explained next), an Outcome<Nothing> is usable as an Outcome<User>.

Variance: in and out

Variance answers a question: if Dog is a subtype of Animal, is Box<Dog> a subtype of Box<Animal>? It depends on whether the box produces or consumes values.

val dogs: MutableList = mutableListOf(Dog()) // val animals: MutableList = dogs // ❌ compile error, and here's why: // animals.add(Cat()) // would put a Cat into a list of Dogs! val readOnly: List = dogs // ✅ List only produces: safe

Kotlin uses declaration-site variance (interface Source<out T>). You can also use use-site variance (fun copy(from: Array<out Any>, to: Array<Any>)) for classes you don't control.

Star projection

List<*> means "a list of some specific but unknown type". You can read elements as Any? but can't add anything. It's useful when you only need type-independent operations, such as size.

Type erasure

On the JVM and Android, generic type arguments are erased at runtime: a List<String> and a List<Int> are both just List. So this doesn't compile:

fun isOfType(value: Any): Boolean = value is T // ❌ Cannot check for instance of erased type: T

Reified type parameters

In an inline function, the compiler copies the body to each call site, where the concrete type is known. Mark the parameter reified and you can use T at runtime:

inline fun Any.isOfType(): Boolean = this is T // Start an Activity without passing ::class.java inline fun Context.startActivity(configure: Intent.() -> Unit = {}) { startActivity(Intent(this, A::class.java).apply(configure)) } // context.startActivity { putExtra("tab", "privacy") } // Filter a mixed feed by type inline fun List.only(): List = filterIsInstance() // Decode JSON without passing a serializer explicitly (kotlinx.serialization) inline fun String.decode(json: Json = Json { ignoreUnknownKeys = true }): T = json.decodeFromString(this)

Libraries use this widely: Hilt's hiltViewModel<T>(), Koin's get<T>() and kotlinx.serialization's decodeFromString<T>() all rely on reified generics.

A practical generic: an in-memory cache

class TimedCache( private val ttlMillis: Long, private val now: () -> Long = { System.currentTimeMillis() }, ) { private data class Entry(val value: V, val storedAt: Long) private val map = mutableMapOf>() private val mutex = Mutex() suspend fun getOrLoad(key: K, load: suspend (K) -> V): V = mutex.withLock { map[key]?.takeIf { now() - it.storedAt < ttlMillis }?.value ?: load(key).also { map[key] = Entry(it, now()) } } } // val profiles = TimedCache(ttlMillis = 60_000) // profiles.getOrLoad(userId) { api.getProfile(it) }

Holding the mutex during load keeps it simple but serialises loads. For high concurrency you'd lock per key.

Common mistakes

  • Over-generalising: a BaseRepository<T, ID, DTO, ENTITY> that every feature fights against. Generic code should remove duplication, not create puzzles.
  • Using Any and casts instead of type parameters.
  • Forgetting that reified requires inline, and that inline functions can't be called from Java with the reified behaviour.
  • Unchecked casts (as List<User>) that hide erasure problems until runtime.

Frequently asked questions

What's the difference between T, T? and T : Any?

A type parameter T may itself be nullable unless bounded by T : Any. T? explicitly allows null. Use T : Any when you need non-null values.

Is Kotlin's out the same as Java's ? extends?

Yes in meaning. out T corresponds to ? extends T, and in T to ? super T. Kotlin adds declaration-site variance so you rarely need wildcards.

Do reified functions increase app size?

Inline functions duplicate their body at each call site, so keep them small. R8 also optimises in release builds.

Conclusion

Generics give you reusable, type-safe code. Variance (out for producers, in for consumers) explains which substitutions are safe. Erasure removes type arguments at runtime, and reified parameters in inline functions bring them back where you need them.
