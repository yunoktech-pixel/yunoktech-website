If your project is Android-only, Retrofit is a safe, well-understood default. If you share networking with iOS through Kotlin Multiplatform, Ktor Client is the natural fit. Everything else in this comparison refines that headline.

The same endpoint in both

interface GithubApi { @GET("users/{user}/repos") suspend fun repos(@Path("user") user: String, @Query("per_page") perPage: Int = 30): List } // val api = retrofit.create(GithubApi::class.java); api.repos("android") val client = HttpClient(OkHttp) { // engine: OkHttp on Android install(ContentNegotiation) { json(Json { ignoreUnknownKeys = true }) } install(HttpTimeout) { requestTimeoutMillis = 15_000 } defaultRequest { url("https://api.github.com/") } expectSuccess = true // throw on non-2xx } class GithubApi(private val client: HttpClient) { suspend fun repos(user: String, perPage: Int = 30): List = client.get("users/$user/repos") { parameter("per_page", perPage) }.body() }

Real scenarios

Android-only app with existing Retrofit code

Keep Retrofit. Migration cost brings no user benefit.

New KMP app (Android + iOS)

Ktor in commonMain with the OkHttp engine on Android and the Darwin engine on iOS.

Gradual KMP adoption

Keep Retrofit in the Android app, and write new shared modules with Ktor behind a repository interface.

Common mistakes

  • Creating a new HttpClient per request in Ktor. Create one and share it, then close it when it's no longer needed.
  • Forgetting expectSuccess = true (or manual status checks) in Ktor, which silently parses error bodies.
  • Mixing both clients for the same API, which doubles configuration (auth, timeouts, logging).

Frequently asked questions

Is Ktor slower than Retrofit on Android?

With the OkHttp engine, both use the same transport. Differences are rarely significant compared with network latency.

Can Retrofit be used in Kotlin Multiplatform?

Retrofit targets the JVM and Android. For shared code that also runs on iOS, use a multiplatform client like Ktor.

Which is easier for beginners?

Retrofit's annotated interfaces are very approachable, and most Android tutorials use them. Ktor's DSL is also straightforward once you know coroutines.

Conclusion

Retrofit remains an excellent default for Android-only apps. Ktor Client is the better fit when networking must be shared across platforms with Kotlin Multiplatform. Either way, hide the client behind repositories so the choice stays reversible.
