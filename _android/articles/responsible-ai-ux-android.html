Users bring very different mental models to AI: some trust it too much, some not at all. Your interface should calibrate that trust, so people rely on AI where it's good, check it where it's weak, and always stay in charge.

Core principles

Set expectations

  • Onboard briefly: what the feature does, examples of good uses, and its limits ("may be inaccurate; check important details").
  • Use specific feature names ("Summarise note") rather than vague "AI magic".
  • Disclose where processing happens (on device or cloud).

Label AI content

@Composable fun AiGeneratedLabel(source: String, modifier: Modifier = Modifier) { AssistChip( onClick = { /* open "About AI summaries" sheet */ }, label = { Text("AI-generated · $source") }, leadingIcon = { Icon(Icons.Outlined.AutoAwesome, contentDescription = null) }, modifier = modifier.semantics { contentDescription = "AI-generated content, from $source. Tap for details." }, ) }

Keep the label when content is saved or shared where appropriate, so its origin isn't lost.

Keep users in control

  • Suggest, don't impose: drafts users edit, not auto-sent messages.
  • Confirm actions with side effects. See Prompt Injection.
  • Undo AI edits (keep the original text).
  • Settings to turn AI features off.

Sources and uncertainty

  • For answers grounded in documents, show citations users can tap. See RAG.
  • Let the model say "I don't know" (instruct it to), and show that state honestly.
  • For high-stakes domains (health, finance, legal), add clear guidance to consult professionals and avoid presenting outputs as authoritative.

Feedback loops

@Composable fun FeedbackRow(onRate: (Boolean) -> Unit, onReport: () -> Unit) { Row(verticalAlignment = Alignment.CenterVertically) { IconButton(onClick = { onRate(true) }) { Icon(Icons.Outlined.ThumbUp, "Helpful") } IconButton(onClick = { onRate(false) }) { Icon(Icons.Outlined.ThumbDown, "Not helpful") } TextButton(onClick = onReport) { Text("Report") } } } // Log ratings without content by default; ask before attaching the response to a report.

Google Play's AI-generated content policy expects apps that generate content to let users report or flag offensive content. Check the current policy for your app type.

Accessibility

  • Announce completion of streamed responses once, not on every token.
  • Make Stop and Retry reachable by screen readers.
  • Make AI labels readable as text, not just icons.

Safety by design

  • Use provider safety settings and your own checks for your audience.
  • Restrict open-ended generation in apps for children or sensitive contexts.
  • Don't make AI impersonate real people or present itself as human.

Launch checklist

  1. Feature explains its purpose and limits.
  2. AI content is labelled; actions require confirmation.
  3. Users can edit, undo, rate and report.
  4. Failures and refusals have helpful messages. See Fallbacks.
  5. Privacy disclosure and settings are in place.

Frequently asked questions

Do disclaimers fix inaccurate AI?

No. They set expectations, but you still need evaluation, grounding and validation to make outputs reliable.

Will labels reduce usage?

Clear labels typically help users calibrate trust appropriately. Hidden AI that later proves wrong tends to damage trust more.

Conclusion

Responsible AI UX sets expectations, labels AI content, keeps users in control, shows sources and uncertainty, collects feedback and reports, and fails gracefully, building trust that outlasts the novelty.
