Our Cloud vs On-Device AI article compares the approaches in general. This one is specific to Google's Gemini family on Android: what Nano can and can't do, what cloud models add, and how to use both.

Two paths to Gemini

Model names and limits change frequently. Current cloud models include gemini-3.8-flash and gemini-3.5-flash-lite. Check the models page before shipping.

Hybrid inference

Firebase AI Logic offers experimental hybrid inference: the SDK uses on-device Gemini Nano when available, otherwise the cloud model:

val model = Firebase.ai(backend = GenerativeBackend.googleAI()).generativeModel( modelName = "gemini-3.8-flash", // cloud fallback onDeviceConfig = OnDeviceConfig(mode = InferenceMode.PREFER_ON_DEVICE), ) val reply = model.generateContent("Rewrite politely: $draft").text

Because the experimental API may change, follow the hybrid inference docs for the exact dependency and names.

Hybrid changes the privacy story

If the feature falls back to the cloud, data leaves the device on some phones. Disclose this, or offer an "on-device only" setting that disables the fallback for sensitive content.

How to choose

  1. Sensitive data, offline need, simple task → Nano where available, with a non-AI fallback elsewhere.
  2. Must work on every device, harder task → cloud Gemini.
  3. Simple task, wide reach, cost-sensitive → hybrid: Nano when present, cloud otherwise.
  4. Long documents or complex reasoning → cloud.

Frequently asked questions

Can I call Gemini Nano with any prompt?

ML Kit's Prompt API allows custom prompts on supported devices, within Nano's smaller capability and context limits. Task-specific APIs (summarise, rewrite) are more tuned.

Is Nano free?

There's no per-call charge, but it only runs on supported devices, in the foreground, within quotas.

Conclusion

Gemini Nano offers private, offline, free inference for simple tasks on supported devices. Cloud Gemini offers stronger models everywhere at a per-token cost. Hybrid inference combines them, with clear disclosure.
